## 审查纪律

### 审查方式

- 始终以完整代码单元（方法/类/静态块等）为审查单位，从整体视角审查，而非仅关注变更片段。
- 产生疑虑时，沿数据流向追溯所需上下文（入口→上游→当前代码单元→下游），基于全链路而非局部片段做判断。

### 误报过滤

标记问题前自问，任一答案为"否"则降级或不报：
- 能精确指出问题位置吗（具体行号或明确到函数/类）？
- 能描述触发条件、影响范围和真实后果吗（如功能故障、数据错误、长期演进成本等）？
- 已确认足够的上下文、从全局代码逻辑看这个问题仍成立吗？

允许零发现，**禁止为体现审查工作而凭空捏造问题**。

### 结果处理

- 问题去重：同一代码单元的同一根因，合并为一条。
- 问题排序：按严重度降序排列，同严重度按代码位置从上到下。
- 问题取舍：优先保留后果最明确、修复最可执行的问题。

### 输出约束

- 只审查，不修改任何代码。
- 修复建议须针对代码单元整体修正根因，而非局部打补丁。
- 修复建议须具体可执行，禁止"请检查""可能有问题"等模糊表述。
