## 审查内容

### 通用安全审查

> 需结合输入来源及调用链综合判定，避免仅凭单点代码判定。

| 风险项 | 判定条件 | 严重度 |
|----------|----------|--------|
| SQL 注入 | SQL 未参数化写入（字符串拼接、MyBatis `${}`） | 严重 |
| 命令注入 | 用户输入未校验即用于执行系统命令（如 ProcessBuilder、Runtime.exec 等） | 严重 |
| 硬编码凭据 | 源码中硬编码敏感凭据（密钥、密码、Token、连接串） | 严重 |
| 路径遍历 | 用户输入构造文件路径，未校验导致目录越界 | 高危 |
| SSRF | 用户输入控制服务端请求地址，未限制目标范围 | 高危 |
| XXE 注入 | XML 解析未禁用外部实体 | 高危 |
| 反序列化风险 | 不可信数据反序列化且无类型白名单校验 | 高危 |
| 日志泄密 | 日志输出敏感凭据或隐私数据（密码、Token、身份证号、手机号等） | 高危 |
| 竞态条件 | 共享可变状态未同步，或检查与使用非原子操作 | 中危 |
| 弱加密 | 采用弱密码学算法（MD5/SHA1/DES 等）或硬编码 IV | 中危 |

### 接口越权

审查接口层认证与授权的完备性。先判定接口类型，再按对应规则执行风险检查。

**类型判定**

- 同时校验类级与方法级特征，依据多数特征的聚集方向判定接口类型。若类级特征与多数方法特征指向不同，以多数方法为准。
- 特征分散无法聚拢时，依以下优先级裁决定型：会话特征 > 方法级权限码 > 类级 @Permission > @TokenRequired > 路径/类名命名。
- 若仍无法归入单一类型，则标记"接口类型无法判定"，跳过该类自动化风险检查，并于审查结果中单独列出所有方法及矛盾特征，待人工分类后重新审查。
- 类定型后，与类类型特征不一致的方法单独列出，按其自身特征补充检查对应风险。

| 特征项 | 前端接口 | 第三方接口 | 微服务接口 |
|---|----------|------------|------------|
| 会话特征 | 含用户级标识 | 仅含租户级标识 | 无 |
| 方法级权限码 | 有 | 无 | 无 |
| 类级 @Permission | 有 | 有 | 无 |
| @TokenRequired | 有 | 有 | 无 |
| 辅助特征 | 类名或路径不含 api、open、endpoint 标识 | 类名或路径含 api、open 字样 | 类名或路径含 endpoint 字样 |

> @Permission 负责将接口及权限码上报至网关；@TokenRequired 负责从请求解析会话。两者职责独立。
>
> 会话特征通过检查是否包含 @UserInfo（或等价注解）及下游读取的字段层级（用户级如 userId，或租户级如 tenantId）来判定，不依赖具体会话类型名。判定信心不足时标记"仍可归类，建议人工复核"，不强行套用前端规则。

**越权检查**

类型已确定后，以下风险项逐一检查。

| 越权项 | 适用接口 | 判定条件 | 严重度 | 危害 |
|--------|----------|----------|--------|------|
| 匿名接口滥用 | 前端接口、第三方接口 | ① 接口标注 @Permission("anonymous()")<br>② 路径/方法名不匹配常见匿名场景（如登录、回调等）<br>③ 方法及直接调用中未见补偿控制（如验签、限流等） | 严重 | 接口无需认证即可访问，可致敏感数据泄露或被恶意调用 |
| 微服务接口暴露 | 微服务接口 | 类级或方法级出现 @Permission | 严重 | 内部接口误配 @Permission 致公网暴露，本无认证授权防护，存在未授权访问风险 |
| 身份认证缺失 | 前端接口、第三方接口（匿名接口除外） | 缺少 @TokenRequired + @UserInfo | 严重 | 缺少认证导致用户身份无法解析，接口退化为无认证访问，可致敏感数据泄露或被恶意调用 |
| 权限码缺失 | 前端接口 | 类上有 @Permission：<br>① 方法未标注 @Permission<br>② 方法标注了 @Permission 但未指定具体权限码（如 @Permission、@Permission()、@Permission("permitAll")） | 高危 | 缺少具体权限码约束，已认证用户可执行未授权操作 |


### 横向越权

已认证用户通过篡改请求中的资源标识，访问或操作不属于自身的资源。在多租户体系中，跨租户访问是其最高形态。

#### 审查方法

从接口层沿调用链逐层校验资源标识的归属约束：
- 归属校验须基于会话中已认证的租户或用户标识，请求方自行传入的归属标识等同于未校验。
- 基于全链路结果统一判定，避免单层未检出即否决；链上任一节点存在有效校验即视为安全。
- 即使上层已校验，仍建议在数据访问层施加隔离约束作为兜底。

| 校验层 | 有效校验 |
|--------|----------|
| 接口层 | 从会话限定资源范围，在限定范围内操作 |
| 拦截器层 | Interceptor / Filter 统一注入归属过滤条件 |
| 业务层 | 显式校验资源归属 |
| 数据访问层 | 查询/更新/删除语句 WHERE 条件含租户或用户过滤 |

**1. 资源标识识别**

从接口层提取请求中的所有资源标识：

| 来源 | 识别方式 | 示例 |
|------|----------|------|
| 路径参数 | @PathVariable | @PathVariable("orderId") |
| 查询参数 | @RequestParam | @RequestParam("deviceId") |
| 请求体字段 | 请求对象中引用业务实体的标识字段 | userIds、deviceIds、deviceSerials |
| 嵌套对象字段 | 请求体内嵌套对象中的资源标识 | order.userId |

补充约束：
- 非主键业务标识（如 deviceSerial、channelId 等）同等视为资源标识；数组或集合类型字段的每个元素均视为独立资源标识。
- 仅追溯参与数据查询、更新或删除条件的资源标识，仅用于参数传递但未约束数据访问范围的不纳入。
- 无具体资源 ID 的列表或范围查询同样纳入审查。

**2. 越权检查**

| 越权项 | 适用接口 | 判定条件 | 严重度 | 危害 |
|--------|----------|----------|--------|------|
| 归属标识来源非法 | 全部 | 归属标识直接取自请求参数而非会话上下文 | 租户标识 → 严重，其他 → 高危 | 导致归属校验被请求参数篡改绕过 |
| 租户归属缺失 | 全部 | 全链路均无租户级归属约束 | 严重 | 导致跨租户访问非授权数据 |
| 用户归属缺失 | 前端接口 | 全链路均无用户级归属校验 | 高危 | 导致已认证用户可越权操作其他用户资源 |
| 关联资源归属缺失 | 前端接口、第三方接口 | 请求体引用的每个关联资源 ID 逐个追溯，全链路均无归属校验 | 高危 | 导致主操作中绑定的关联资源遭越权访问 |
| 范围过滤缺失 | 前端接口、第三方接口 | 列表或范围查询未在数据访问层或拦截器层施加用户级/租户级 scope 过滤 | 高危 | 导致突破归属限制获取全量数据 |

### 纵向越权

低权限用户执行高权限操作。以下仅覆盖部分场景。

| 越权项 | 判定条件 | 严重度 |
|--------|----------|--------|
| 角色标识来源非法 | 角色标识（role、roleId、userType 等）直接取自请求参数 | 严重 |
| 方法级权限缺失 | 类上或同类其他方法存在角色限定，本方法未标注 | 高危 |

### 数据隔离

检查数据存取及基础设施资源是否按隔离维度施加了约束。隔离维度包括租户、部门、项目等，以实际业务为准。

| 风险项 | 判定条件 | 严重度 |
|--------|----------|--------|
| 读操作未隔离 | 查询未按隔离维度过滤 | 严重 |
| 写操作未隔离 | 新增未绑定隔离维度，或修改/删除未按隔离维度限定范围 | 严重 |
| 资源 Key 未隔离 | Redis Key、分布式锁 Key 等未包含隔离维度 | 高危 |

以下以租户隔离为例：

```text
- 读操作未隔离：
    反例：SELECT * FROM device WHERE id = 1
    正例：SELECT * FROM device WHERE id = 1 AND tenant_id = #{tenantId}

- 写操作未隔离：
    反例：INSERT INTO device (name, status) VALUES ('xxx', 1)
    正例：INSERT INTO device (name, status, tenant_id) VALUES ('xxx', 1, #{tenantId})

    反例：UPDATE device SET status = 0 WHERE id = 1
    正例：UPDATE device SET status = 0 WHERE id = 1 AND tenant_id = #{tenantId}

    反例：DELETE FROM device WHERE id = 1
    正例：DELETE FROM device WHERE id = 1 AND tenant_id = #{tenantId}

- 资源 Key 未隔离：
    反例：Redis Key：device:status
    正例：Redis Key：device:status:{deviceId}

    反例：分布式锁：lock:import
    正例：分布式锁：lock:import:{personId}
```

**排除项**

- 无多维度隔离需求的系统跳过隔离检查
- 公开数据表（字典表、配置表）的读操作不检查隔离

### Token 泄露

| 风险项 | 判定条件 | 严重度 |
|--------|----------|--------|
| 萤石 Token 暴露 | 萤石 accessToken 直接返回给前端 | 严重 |
| 对象存储临时凭证暴露 | 业务接口返回 OSS/COS/S3 临时凭证，应由框架统一封装 | 严重 |

## 严重程度定义

| 级别 | 图标 | 标准 |
|------|------|------|
| 严重 | 🔴 | 可直接导致系统被控、核心数据大量泄露或核心业务瘫痪 |
| 高危 | 🟠 | 可获取较高权限、窃取敏感数据或绕过关键安全控制 |
| 中危 | 🟡 | 存在安全缺陷，但利用受限或影响有限 |
| 低危 | 🔵 | 几乎无实质性安全影响 |

