## 审查流程

### 步骤一：解析审查维度

从 `$ARGUMENTS` 或对话描述中解析审查维度。非法值报错终止，均未指定时默认全部维度。

- `quality` — 质量审查
- `security` — 安全审查

### 步骤二：确定审查范围

1. **确认意图与范围**

   - 若用户已明确指定范围 → 直接采用该范围
   - 若用户意图模糊或未指定 → **主动询问用户**，并引导用户选择

2. **过滤非关键文件**

   - 根据上一步确定的文件范围，自动过滤非关键审核文件（如说明文档）
   - 对文件审核必要性存在争议时，禁止自行决定，须询问用户确认

3. **校验最终范围**

   - 若最终确定的审核范围为空 → 回复”没有需要审核的内容。”并终止流程

> 严禁在未明确用户意图前执行任何操作，必须优先询问并引导用户确认

### 步骤三：分发审查

将审查文件进行分组，并分别交由对应维度的 reviewer agent 审查。映射关系如下：

- `quality` → ym-quality-reviewer
- `security` → ym-security-reviewer

规则：

- 同一组件/模块或存在关联的文件尽量同组
- 同类型 agent 并发上限 5，超出排队

### 步骤四：审查度复核

同一维度的审查 agent 全部完成后，立即启动 ym-review-verifier agent 对该维度的全部结果逐条复核

### 步骤五：输出报告

全部复核完成后，合并去重，按以下规则输出：

- 结果 ≤10 条 → 控制台输出
- 结果 >10 条 → 输出 HTML 文件到 `reports/code-review/{branch}-report-YYYYMMDDHHmmss.html`

控制台格式：

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  代码审查报告
  审查日期：YYYY-MM-DD | 分支：<branch> | 审查模式：<mode>
  审查文件数：N 个

  审查总结：<1-2 句话整体评估>
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

N、质量审查
- 无问题时: [未发现质量问题]
- 有问题时: 逐条列出问题，附带关键代码片段与修复建议

N、安全审查
- 无问题时: [未发现安全问题]
- 有问题时: 逐条列出问题，附带关键代码片段与修复建议

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  审查统计：
  | 维度 | 高危 | 严重 | 中等 | 建议 | 合计 |
  |------|------|------|------|------|------|
  | 质量 | 0    | 1    | 2    | 0    | 3    |
  | 安全 | 1    | 0    | 0    | 0    | 1    |
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

HTML 输出要求：
- 导航层级：组件 tab → 维度 tab → 严重度筛选，三层联动
- 每条问题默认折叠，点击展开显示描述、关键代码片段和修复建议
- 提供”全部展开/全部折叠”切换
- 筛选联动：切换组件、维度、严重度时自动过滤问题列表
- 风格简洁专业，深色头部 + 浅色内容区

### 步骤六：引导后续操作

输出报告后，引导用户是否继续修复。
