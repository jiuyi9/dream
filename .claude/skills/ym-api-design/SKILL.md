# 云眸 API 接口设计文档生成

## 适用范围

**适用场景**

- Web 接口（面向于 Web、H5、App 及小程序等前端应用）
- 开放接口（面向第三方开发者）

**不适用场景**

- 微服务接口（面向内部微服务）

## 使用时机

- 设计阶段，生成符合云眸 API 规范的接口设计文档
- 编码阶段，从代码中提取接口信息，生成标准化的接口设计文档

## 技能能力

- **提取接口信息**：从设计或代码中提取接口定义
- **对齐云眸规范**：将接口信息按云眸 API 规范进行标准化（如：响应结构、分页约定、参数命名等）
- **生成设计文档**：依据模板渲染并输出完整文档至指定目录

## 工作流

### 步骤一：确认基础信息

逐项推导以下信息，无法确定时主动询问；汇总后交用户确认，确认无误再进入步骤二。

1. **接口类型**

   - `web` — Web 接口
   - `open` — 开放接口

   确定后分别查阅 [云眸接口规范](../../shared/ym-api-spec.md) 与下方 [接口设计文档模板](#接口设计文档模板) 的对应章节，为后续步骤做准备。

2. **版本号**

   从 `docs/apis/{web|open}/` 目录下已有文件命名推导（如 `v1.0.0_接口设计文档.md` → `v1.0.0`）

3. **URL 路径前缀**

   从模块目录提取业务标识与组件标识，按规范中的路径前缀定义拼接：

   ```
   siot/                   ← 业务标识：siot
   ├── siot-video/         ← 组件标识：video
   ├── siot-device/        ← 组件标识：device

   Web 接口：  /v1/siot/video
   开放接口：  /siot/video/api
   ```

### 步骤二：提取并对齐接口

**总体原则**：以云眸接口规范为约束、以接口设计文档模板结构为框架提取并对齐接口，存在疑问时主动询问用户

| 输入来源 | 接口提取方式 | 对齐原则 |
|---------|---------|------|
| 设计 | 从已有的设计中提取接口信息 | 以设计意图为指引 |
| 代码 | 扫描指定范围的 Controller 代码（`@RequestMapping`、`@GetMapping`、`@PostMapping` 等）提取接口信息 | 事实（路径、参数名、字段名、请求结构等）不得篡改；规范约束（如响应结构、分页约定等）仍须对齐 |

### 步骤三：生成并保存设计文档

按对应接口设计文档模板输出文档，写入 `docs/apis/{web|open}/{版本号}_接口设计文档.md`
